# 架构说明

## 系统边界

ShareSub 只处理 OpenAI Codex 账号共享。系统没有通用平台适配层、计费或支付模块。Plan 可通过一次性邀请链接加入，也可预留固定席位后发布到大厅，由房主审批申请。

系统由五个明确的业务上下文组成：

1. **身份**：管理用户、邮箱验证与不透明登录会话。
2. **账号**：管理 OpenAI OAuth 状态、加密凭据、Token 刷新和账号健康状态。
3. **共享**：管理公开/私密 Plan、一次性邀请链接、公开申请、成员和固定/共享额度方式。
4. **访问密钥**：管理用户级 API Key、Key 到多个 Plan 的路由和选路策略。
5. **网关**：在请求发出前选定一个可用 Plan，转发 Codex 流量并记录额度与性能指标。

每次转发前都会解析以下链路：

```text
用户 API Key -> 启用的 Plan 路由 -> 用户在该 Plan 的有效成员 -> 房主的有效 OpenAI 账号
```

`priority` 按路由优先级选择，并在请求尚未发出时跳过额度耗尽、固定份额为 0 或凭据不可用的 Plan；`balanced` 在固定分配模式按“成员估算用量 / 成员份额”比较，在共享模式按账号总额度使用比例比较，优先级用于比例相同的排序。账号绑定 Plan 前已有的额度消耗不分摊给成员。上游明确以 `429` 或 `529` 拒绝执行时最多切换 3 个账号；连接错误、超时和其他响应不重试，避免重复执行。

## 核心关系

- OpenAI 账号归完成 OAuth 授权的 ShareSub 用户所有，只有所有者可以修改账号配置。
- 账号可配置名称、备注、调度状态、独立代理、最大并发和 RPM 上限；OAuth 接入、重新授权以及自动或手动 Token 刷新会同步当前付费订阅有效期，账号所有者和平台管理员可手动刷新单个正常账号，Plan 的所有有效成员都能查看所绑定账号的完整配置。
- 一个共享方案最多绑定一个 OpenAI 账号；创建时可以暂不绑定，未绑定方案可以进入公开大厅招募成员，但不会进入网关/API Key 路由。
- 房主创建方案时也会成为该方案的成员。固定分配模式占用设定份额（允许为 `0`），共享模式的成员份额为 `0`。
- 邀请链接不绑定邮箱，7 天内可由第一个完成登录或注册的用户领取一次。
- 公开 Plan 上架前必须设置席位数；固定分配模式还需设置每席份额（允许为 `0`），共享模式的每席份额为 `0`。
- 房主批准申请时立即创建成员，并占用一个公开席位。
- 一个用户可以创建多个 API Key，每个 Key 可以绑定一个或多个自己已加入的 Plan。
- 固定分配模式下，房主、成员、邀请和公开席位份额允许为 `0`；0% 成员保留 Plan 查看权限但不能通过该 Plan 发起请求。有效成员、未过期待接受邀请和尚未占用的公开席位预留份额之和不能超过 `10000` 基点，即 100%。共享模式不分配个人份额。

## 安全设计

- 用户密码使用 bcrypt 哈希。
- 登录 Token、邮箱验证 Token、邀请 Token 和用户 API Key 都是随机不透明值，数据库只保存加入 Pepper 后的 SHA-256 哈希。
- 新注册用户必须通过腾讯云 SES 收到的事务邮件完成邮箱验证，验证 Token 默认 1 小时有效且只能使用一次。重新发送默认冷却 1 分钟，同一用户每小时最多 5 次；新 Token 创建时会使此前未使用的验证 Token 失效。
- 验证链接把完整 Token 放在 URL fragment 中，避免 Token 进入反向代理和服务端访问日志；验证页面还要求用户明确点击确认，避免邮件安全扫描器自动消费链接。
- OAuth access token 与 refresh token 使用 AES-256-GCM 加密保存。
- OAuth access token 由后台任务提前刷新，请求路径负责临近到期兜底；数据库租约锁串行化同一账号的多实例刷新，写回时按原 refresh token 做条件更新，避免覆盖并发重新授权。
- 账号独立代理使用 AES-256-GCM 加密保存；账号代理优先于系统全局代理，代理请求失败时不会回退直连。
- OAuth 使用 PKCE；state 记录只能使用一次，并在 15 分钟后过期。
- 接受邀请通过事务锁定邀请记录，保证同一链接只能成功领取一次。
- 网关费用指标使用上游请求 ID、API Key 和账号组成幂等键，避免同一次账号尝试重复记账。
- 完整邀请 Token 只嵌入创建时返回的 fragment 邀请链接；完整 API Key 使用独立关联数据加密保存，只有密钥所有者登录后可以反复查看。
- 网关指标保存成员、端点、请求方式、请求/上游/计费模型、状态码、语义 TTFT、总耗时、Token/Cache Creation/图片/Web Search 用量和费用拆分。非 2xx 请求额外保存错误来源、错误代码和最多 2000 字符的结构化错误消息；不保存请求正文或完整响应体。

## Codex 身份隔离与指纹收敛

Responses HTTP 与 WebSocket 的出站身份先按本地稳定账号 ID、API Key ID 和原始客户端标识确定性隔离，再应用可选的指纹收敛。请求头、`client_metadata` 及其中的 turn metadata 使用相同映射；`prompt_cache_key` 同样隔离，与原始会话标识相同的缓存键跟随最终会话标识。换号重试始终从原始客户端请求重新计算，不对已改写值重复隔离。compact 只处理请求头，保留其严格的正文白名单。

新账号默认 `off`，保留不同客户端设备、会话和对话之间的区别。显式 `device`、`session`、`full` 继续提供原有收敛行为；迁移 `037` 仅修改数据库列默认值，保留所有既有账号配置，重新授权也保留配置与账号 ID。切换隔离映射可能使旧会话或缓存失效，客户端重新建立会话后使用新的稳定标识。

## 额度模型

OpenAI 会在 Codex 响应头中返回主窗口和次窗口的使用信息。ShareSub 根据窗口时长识别含义，不依赖响应头出现顺序：

- `300` 分钟：5 小时窗口
- `10080` 分钟：7 天窗口

每次成功响应后，ShareSub 更新账号窗口的已用额度快照。同一窗口只接受更高的已用百分比；较低的乱序观测不会覆盖现有值。额度快照只描述账号窗口状态，不承担成员费用分摊。

百分比以一个百分点的百万分之一为单位，使用整数保存，避免浮点数累计误差。例如 25% 保存为 `25000000`。固定分配模式分别在 5 小时和 7 天有效窗口内使用统一公式：`max(账号当前已用额度 - 本次 Plan–账号绑定的当前窗口基线, 0) × 成员同期请求费用 ÷ 全部成员同期请求费用`。同期请求费用只统计当前绑定代次和对应额度窗口内的 `estimated_cost_micros`；任一窗口的成员估算额度达到其份额后不再参与选路。共享模式不执行个人额度限制；账号任一有效窗口达到 100% 后不再参与选路。

只有完整、可识别的 5 小时或 7 天额度信号才会写入额度快照。额度头缺失时不会猜测窗口或使用其他字段替代，也不会把已经成功的上游响应改写成网关错误。

网关不设置应用级总请求并发上限，避免少量长时间 SSE 请求阻塞其他用户和账号。HTTP 请求与 Responses WebSocket 的每个 turn 发出前，都按账号执行最大并发与固定自然分钟 RPM 限制。HTTP 请求以及 WebSocket 首轮选路时，某个候选账号达到限制会继续尝试当前 API Key 的下一个候选 Plan；WebSocket 后续 turn 固定原账号，不再切换账号，固定账号不可用时要求客户端重连。账号限制器位于 API 进程内，单实例部署时覆盖全部请求。

Responses WebSocket 连接另有独立的进程内入口限制，默认每个用户 API Key 最多 64 条连接；这项连接限制不替代账号业务并发。连接只在活跃 turn 期间占用账号并发槽，终止事件后立即释放，轮间保持上游热连接但不占业务并发。首轮固定 `(API Key, Plan, Member, Account, Account Binding Generation)`；后续 turn 必须重新验证该绑定、额度、RPM 和并发，不能把会话状态迁移到其他账号。

账号当前配额窗口以 `(account_id, window_type)` 唯一标识。上游 `reset-after` 响应头存在秒级漂移时，网关复用已锁定窗口的起止时间，避免同一窗口被拆分成多份。

Plan 详情与固定份额网关限制使用同一口径：在当前 Plan–账号绑定代次中，从绑定探测完成时间开始汇总 `estimated_cost_micros`，用成员费用占比乘以账号窗口扣除绑定基线后的用量。成员加入、退出、重新加入或调整份额都不会重置该基线；换绑会开始新的绑定代次。

## 仪表盘口径

HTTP 流式请求在首个语义输出前暂存 SSE 前导事件；若此时收到可重试的 `response.failed`，可以安全切换账号。前导事件累计达到响应缓冲上限时会立即开始透传并放弃后续切换，避免无界占用内存。首个语义输出发出后不再切换。HTTP 客户端中途断开时会取消当前上游请求并释放在线并发，不再继续读取响应或发起新账号尝试。usage 只从固定终止事件读取，包含 Input/Output/Cached/Cache Creation/图片 token，并统计完成的图片生成与 Web Search 调用；若流在终止事件前异常关闭，网关补发 `response.failed`。非流式请求会读取上游 SSE 直到终止事件并返回对应的 JSON response，compact 的 JSON 响应直接转发。

Responses WebSocket 端到端复用一条 ChatGPT Codex 上游连接，每个 `response.create` 到固定终止事件构成独立 turn，并分别记录 usage、TTFT、总耗时与成本。仅首轮零下行时，握手 `429` 或明确的 rate/usage/quota error 可触发换号，最多切换 3 次；任一下行后、客户端发出 `response.cancel` 后及后续 turn 不换号、不重放。首下行前的 cancel 会立即发给当前上游，并将当前 attempt 固定为不可换号。客户端在活跃 turn 中断开后，网关停止向客户端写帧，并在默认 1.2 秒的短窗口内继续读取上游终止事件以尽量保留真实 usage；到期会立即释放本 turn 的账号槽位，不会长期占用并发。账号代理优先于全局出站代理，连接建立后若账号代理配置发生变化，后续 turn 会关闭连接并要求客户端重新建立新连接。

“今日”按前端提交的 IANA 时区计算，趋势始终返回包含当前小时在内的最近 24 个小时桶。RPM 与 TPM 使用最近一分钟滚动窗口；平均 TTFT、平均总耗时、成功率与实际使用的 Plan 数使用今日窗口。Token 指标迁移前的历史记录统一为 0，因此准确累计从迁移上线后的新请求开始。

Plan 成功率和错误明细使用完全相同的成员权限、时间窗口和网关指标口径。HTTP 非 2xx、网关本地拒绝以及 HTTP 为 2xx 但固定终止事件为 `response.failed` 的请求都计入错误；明细按照时间倒序分页，历史记录在结构化错误字段上线前只显示已有状态码。

## 数据与迁移

数据库使用 PostgreSQL。迁移文件嵌入后端二进制，API 每次启动时按文件名顺序自动执行未应用的迁移，并把结果记录在 `schema_migrations` 表中。

主要数据包括：

- 用户与登录会话
- 邮箱验证 Token 与验证状态
- OAuth 流程与 OpenAI 账号凭据
- 共享方案、成员和邀请
- 公开申请与审批记录
- 用户 API Key 与多 Plan 路由
- 账号额度快照与 Plan–账号绑定窗口基线
- 网关性能与 Token 指标
- 审计事件

## 请求路径

管理请求通过 `ss_session_...` 登录 Token 鉴权，由 `/api` 路由处理。Codex 请求通过 `sk-sharesub-...` 用户 API Key 鉴权，由 `/v1/responses`、`/responses` 或 `/backend-api/codex/responses` 进入网关；三个路径的 `POST` 处理 Responses HTTP，`GET` 处理 Responses WebSocket Upgrade。三个前缀都支持仅使用 HTTP 的 `/compact`，并分别提供独立 SearchClient 使用的 `/alpha/search`。

Docker 部署时，外部请求先到 Web 容器中的 Nginx。静态页面直接返回，`/api/`、`/v1/`、`/responses` 和 `/backend-api/` 转发到 API 容器。网关路径关闭代理缓冲，并为 Responses 路径透传 `Upgrade` 与 `Connection` 请求头，以同时支持 SSE 和 WebSocket。

## 代码组织

后端保持 `domain -> application -> infrastructure` 的依赖方向：

- `internal/domain` 定义稳定的业务模型和错误。
- `internal/application` 按身份与账号、Plan、网关访问拆分用例；`ports.go` 是持久化与 OpenAI 能力边界。
- `internal/postgres` 按账号、Plan 查询、Plan 协作、Key 与指标组织 SQL；跨多表生命周期事务单独放在 `lifecycle.go`。
- `internal/httpapi` 的 `server.go` 只负责服务构造和路由总览，管理接口、网关接口和 HTTP 通用能力分别实现。
- `internal/openai` 将请求准备与发送、响应复制与计量、OAuth 分开。

前端页面只负责组合 UI。跨多个模板区域共享的状态和命令放在同目录 composable 中；页面专属样式使用同名 CSS 文件，全局基础样式与业务功能样式分开。API 数据直接使用 `types.ts` 中与后端契约一致的固定类型，不在视图层转换或猜测返回结构。

## 并发分配与历史

账号并发仍是单个后端进程内的在途请求名额；HTTP 请求在网关准入时申请、处理结束时归还，Responses WebSocket 每轮申请和归还，空闲连接不占账号并发。session、API Key 和 subagent 不是独立的计数主体。同一账号下的请求按用户 ID 合并，用户的多个 Key 共用成员限制。

Plan 可开启「基础名额专属保留 + 共享并发池 + 个人上限」。新旧 Plan 默认关闭，保留原先仅按账号总上限控制的行为。开启时账号必须配置有限上限 `C`，所有有效成员基础名额之和 `B` 必须不超过 `C`，共享池容量为 `C-B`。成员占用低于其基础名额时使用基础名额；超过基础的部分竞争共享池，同时受个人上限约束。个人上限为 0 表示跟随账号上限。所有检查及增减在同一个准入锁内完成；不排队、不抢占、不打断已开始的请求。

基础名额不能借给别人。共享使用量根据每位用户的 `max(当前请求数-基础名额,0)` 重新计算，避免请求乱序结束导致名额泄漏。成员移除后其仍在途的请求按共享占用计算，释放逻辑仍然有效；退出和重新加入均清零该成员的分配配置。新增成员默认基础 0、个人上限 0。房主和管理员可以一次保存所有有效成员的配置，服务端检查权限、成员集合和容量，记录 `plan.concurrency_updated` 审计。更改配置只作用于后续准入；降低限制后，已有请求自然结束期间可能暂时超过新限制。账号降低总上限或换绑时，也必须满足已开启的基础预留总额。

并发历史从网关请求的实际名额申请与释放采集，与 Token 计费指标分开。额度查询用于生命周期互斥的内部预留不归属成员，不计入网关并发图表。在每次计数变化时按持续时间积分，并记录每分钟同一时刻的实际总峰值，不把成员各自的峰值相加。完整分钟的成员平均值为该分钟的请求占用秒数除以 60；采集刚开始、重启或当前未结束分钟只除以已观测秒数。各成员平均值相加等于总平均并发。无采集数据的分钟表示未知，前端留空，不补成零或从已完成请求倒推。

采集器每 5 秒将有变化的分钟快照批量写入 PostgreSQL，写失败保留待重试快照，读取时用当前进程快照覆盖同一采集器的已落库版本，避免重复累计。快照按采集器 incarnation、账号、Plan、绑定代次、分钟唯一；采集器过期重建或服务重启不覆盖旧快照。内存保留约 25 小时，数据库分钟历史保留 48 小时，并由资源清理任务分批清除。停机时尝试最终刷新；进程崩溃可能丢失最后尚未持久化的片段（正常写入时约 5 秒，数据库故障时更长）。已写入历史重启后仍可查询。换绑后图表只展示当前账号与当前绑定代次，避免把不同账号或前一共享关系的记录混在一起。

该机制延续当前单后端实例的运行边界，不提供跨进程分布式并发限制，也不把多个同时运行的后端实例当成一个准确的全局并发历史。多实例部署需要另行实现统一准入与全局采集。直接登录上游账号、未经过 ShareSub 的请求不在统计范围内。

### 固定出口 Codex STATE

`application.CodexStateService` 通过小型账号读取、`CodexStateStore` 和 `CodexStateProber` 端口编排探测/验证/续期；启动层向 `openai.Gateway` 注入 `CodexStateController`。`openai` 负责 SSE 完成检查、上游探测、HTTP 注入和只读响应观察，`postgres` 负责租约、条件写回和配置变化撤销。状态管理接口复用用户鉴权，账号所有者或管理员可访问。功能默认关闭，普通转发不依赖票据成功。完整运行边界见 `codex-state-integration.md`。
