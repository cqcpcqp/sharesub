# 固定出口 Codex STATE

账号配置的 `state_enabled` 默认关闭。功能实验性支持 Pro、Team / Business，使用账号代理；没有账号代理时使用服务当前全局代理/环境代理或直连。不需要动态代理池。

## HTTP 运行流程

1. 开启后，普通 HTTP Responses 请求完整成功且返回模型精确匹配后，才登记目标模型。模型不存在、权限拒绝、失败或未完成响应不占任务名额。首次请求不等待探测，按原有方式转发。
2. 后台每 15 秒扫描到期任务，每实例最多同时执行 2 个作业；数据库 3 分钟租约避免同一账号模型重复采集。
3. 固定出口每轮最多采集一次、验证一次。采集必须取得完整成功 SSE 响应、精确匹配的模型和 Pro 292 / Team 332 字节格式的候选 STATE；再携带候选票据通过同一业务出口验证。有效格式的 312 字节信号拒绝候选。
4. 通过验证后使用现有 AES-GCM 密钥加密保存。票据作用域包括账号、模型、套餐、刷新凭据、账号代理、指纹设置和全局出口配置。后续普通 HTTP Responses 请求覆盖客户端 STATE 头，使用已验证票据。
5. TTL 为采集开始后的 60 分钟，提前 10 分钟续期。失败冷却 5 分钟；401/403/429 立即停止本轮。无动态出口可切换，不重复进行参考实现的 8 次轮换探测。续期失败保留仍有效的旧票据。
6. 业务响应出现有效 312 信号，或完整成功响应实际模型不匹配时，按请求使用的版本撤销票据；不会撤销并发替换的新票据，不会重放已完成请求。
7. 没有可用票据、数据库不可用或验证失败时，继续普通转发，包括原有客户端 STATE 头。关闭开关时走原有路径。

每账号最多登记 8 个最近使用的模型。24 小时无 HTTP 请求的模型任务清理；到期票据不再注入。关闭开关、账号状态/代理/套餐/指纹或刷新凭据变化时，数据库触发器删除票据及作业，旧租约不能写回。进程重启后有效密文可复用，配置指纹变化时重新采集。配置相同但实际出口 IP 改变无法由配置指纹识别，需要重新验证。

## 使用与限制

保存开关后，重新打开账号配置查看每模型状态、最近结果、尝试轮数、到期时间与下次探测时间。支持更新状态和提前重新验证可用票据；失败冷却不允许手动绕过。未使用过的模型在首次完整成功且模型匹配的请求后登记。

探测遵循同一进程的账号并发和 RPM 上限，账号繁忙时跳过并冷却。探测真实消耗上游账号额度；探测不属于某个成员业务请求，不记入成员请求计费。探测只有最小 ping/pong 内容，不使用用户业务输入。

当前只应用于普通 HTTP Responses（流式与非流式客户端均支持，因为上游为 SSE）。`/responses/compact`、Images、模型列表及原生 WebSocket 不注入，也不登记模型。WebSocket HTTP bridge 的用户确认仍待完成，尚未实现。

长度和模型匹配仅证明通过这套实验验证，不证明解除降智、风控、封禁或恢复额度，也没有真实上游效果保证。运行状态仅保存最近一轮结果，不保存完整活动历史或出口 IP 追踪。

## 验证

单元测试覆盖格式、作用域、SSE 分片/超限、完成模型判定、关闭路径、注入/失效、加密、二次验证与续期失败。
独立 PostgreSQL 测试覆盖迁移、开关保存、租约互斥、旧收据隔离、撤销后失败续期不得复活、配置变化、模型数量上限。
未调用真实上游账号验证效果，也未打开浏览器测试。

票据查询与任务登记携带本次网关请求的账号配置快照（身份、套餐、刷新凭据、代理、指纹模式），与最新配置不匹配时跳过；登记事务在账号行锁内再次核对，旧请求不能删除新配置的票据。保存相同代理明文复用已有密文，名称/备注修改不会触发代理撤销。
