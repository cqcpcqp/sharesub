# 用户会员、房主名额与易支付

## 最终业务规则

- VIP：990 分 / 720 小时；SVIP：1990 分 / 720 小时，包含 VIP 权益。
- 有效 VIP 补 1000 分升级 SVIP，到期时间不变，不另外赠送 30 天。有效 SVIP 不允许购买 VIP；到期后可重新选择等级。同级提前续费接原到期时间，已到期从后端确认付款时起算。
- Plus、Pro 均按调用用户的会员资格授权，不再按 Plan 收取 49.9 元，也不要求绑定 Pro 前付款。会员不包含 OpenAI 账号、订阅、额度或拼车席位，不自动扣款。
- 会员到期仅阻止该用户的新 API 请求。HTTP 和 WebSocket 后续轮次重新校验；已开始的一次响应允许完成。不影响同一 Plan 的其他有效会员，不删除 Key、Plan、成员或历史数据。续费后原 Key 恢复使用。
- 会员中心在「个人设置」顶部，展示状态、到期时间、来源、房主名额、商品与订单。会员通知链接指向个人设置；管理员待处理通知指向后台。

## 房主资格与名额

- 有效 SVIP 默认同时拥有最多 2 个未归档 Plan，空 Plan 也计数。不是累计创建次数。
- 创建、接收转让和恢复归档 Plan 都检查资格和数量，加入他人的 Plan 不占名额。转入归档 Plan 仍需 SVIP，但归档 Plan 不占名额，恢复时重新检查。
- 管理员可配置个人覆盖值（0–10000），null 表示跟随默认 2 个。0 不是无限制。覆盖额度不授予永久 SVIP。
- SVIP 到期或改买 VIP 后，已有 Plan 保留，房主仍可维护账号授权、已有成员份额、移除成员、归档及转出。不能创建/接收/恢复 Plan 或增加成员。邀请创建、邀请接受、申请批准和扩大公开招募均由后端检查房主资格，防止旧邀请绕过限制。
- 调低上限不移除已有 Plan，只阻止继续新增。名额覆盖在后续续费、升级后仍保留，归档释放名额。

## 首次启用与存量赠送

数据库迁移不会启用会员制。管理员在「后台管理 → 支付设置」首次明确确认「启用收款」时，在同一事务内写入全局启用时间并赠送：

1. 当前拥有至少一个未归档 Plan 的用户：30 天 SVIP。
2. 其他当前属于未归档 Plan 的有效成员：30 天 VIP。
3. 已拥有超过 2 个未归档 Plan 的房主：设置个人上限为实际数量（保留更高的既有覆盖），属于可重复利用的正式名额。
4. 重复身份只赠送最高等级一次，不累加天数。纯注册用户、仅有归档 Plan 的用户、待审批申请和未接受邀请不计入。

重启、多实例、重复启用均不重赠。停用在线收款不撤销会员门禁。管理员可在启用前人工授权，迁移赠送不会缩短已有更长权益。启用前原使用行为保持不变。

首次启用与 Plan 房主、成员扩张操作通过事务表锁协调：相关操作在读取会员资格及取得行锁前先取得 Plan 写意向表锁，启用事务取得共享表锁后再执行赠送。启用期间等待的操作必须在启用提交后读取新的会员资格，不能沿用启用前的免费状态。正常 Plan 操作之间的写意向表锁互不排斥；同一用户的名额判断仍通过用户行锁保护。

## 支付配置和契约

保留后台配置的易支付网关、PID、商户密钥。密钥加密保存、留空保持、不回显、不记入日志或审计。数据库配置优先；环境变量 `SHARESUB_EASYPAY_URL/PID/KEY` 仅提供首次填写来源，不自动开启收款或会员制。

- ZPAY 网关基础地址按所提供文档为 `https://zpayz.cn`，不带接口文件名。凭据必须来自实际商户，不能使用文档示例。
- 站点公开地址必须是公网 HTTPS。本机配置 `SHARESUB_PUBLIC_URL`，Docker 使用 `SHARESUB_DOCKER_PUBLIC_URL`；页面仅检查地址格式，不代表验证公网连通或真实商户兼容。
- 页面跳转 `submit.php`，支持支付宝/微信；不引入二维码、多商户分流、钱包或退款系统。
- 订单号 32 位纯数字；金额由后端按商品固定，不接受前端定价。
- 下单传入无查询参数的 `/api/payment/easypay/notify` 与 `/api/payment/return`。同步返回验签后只跳转会员中心，不发放权益。
- 异步通知验签、核对商户/订单/金额，事务内更新订单、会员、审计和通知。重复回调幂等，商户交易号按商户与网关唯一。
- 查单使用 HTTPS GET `api.php?act=order...`，严格按文档固定字段类型解码，无返回结构猜测。错误消息不包含带密钥的 URL。
- 每用户一个待付订单，同商品复用；不同商品需先核实或取消旧待付订单。取消仅结束本地待付状态，不保证关闭上游交易；迟到款项仍处理。
- 每分钟补查最近 7 天待付/过期订单，每批最多 20 笔，同单后台间隔至少 5 分钟；手动核实间隔至少 15 秒。历史超过自动窗口仍可手动查单。

## 升级晚到账与人工处理

升级订单保存下单时的会员版本和原到期时间。如果到账时 VIP 已到期、会员被管理员调整/续费，或者普通套餐到账时当前有效等级已不同，不猜测如何覆盖权益：记录真实到账与交易号，订单进入 `review_required`，通知用户和管理员。重复通知不会重复发放或丢失款项。

管理员在用户「会员与名额」中核实记录，点击「处理已到账订单」，明确填写等级、到期时间及原因，原子更新权益与订单已处理状态。该操作不执行退款。需要退款时，在支付商户后台人工核对处理，不把未退款订单假装退款成功。

管理员授予、终止、补时和额度覆盖留审计，不伪造付款订单，使用版本校验防止并发覆盖。已付款订单与会员权益不进入短期清理。

## 旧方案迁移安全

旧 Plan 付款入口、49.9 商品、Pro 绑定门禁、Plan 到期过滤和对应 UI 已删除。029/030 迁移文件保留原内容，不能修改已执行迁移的校验和；031 新增会员表，旧表不再参与业务。旧商户配置保留，但旧开启状态关闭，必须按新的会员规则重新明确启用。

031 检查旧 Plan 订单：如果存在任何记录，迁移拒绝执行，必须先核实有无真实付款并制定迁移安排，不会静默删除或丢弃旧订单。这里不提供自动删除历史付款的脚本。

代码升级、生产迁移和正式启用会员制是独立操作。本次开发不表示生产已经升级，也不表示已完成真实付款联调。发布前需备份、确认旧订单检查、公告新收费规则，并在明确授权后完成一笔真实付款及权益核对。
