# 数据治理规范

本文汇总 ShareSub 已有的数据边界，并为新增数据建立评审清单。具体字段和接口结构仍以 `docs/api.md`、migration 和 Go 类型为准。

## 治理原则

1. **目的限定**：只保存身份、账号共享、路由、额度、性能和安全审计所需数据。
2. **最小持有**：网关不保存完整请求正文或完整响应正文；错误消息为长度受限的结构化信息。
3. **确定口径**：单位、窗口、时区和聚合公式必须在写入与展示端保持一致。
4. **生命周期明确**：短期流程数据按过期时间清理，指标按保留策略汇总，凭据随资源生命周期撤销或删除。
5. **契约唯一**：后端响应是固定契约；前端直接使用对应类型，不实现结构 fallback。

## 数据分类

| 分类 | 典型数据 | 保护要求 |
|---|---|---|
| 公开 | 公开 Plan 描述、公开用户名和头像 | 仅暴露接口明确允许的字段 |
| 内部业务 | Plan、成员、份额、申请、通知、路由配置 | 登录鉴权并按成员/所有者权限过滤 |
| 行为指标 | Token、费用估算、TTFT、状态码、额度窗口 | 不附带完整请求/响应正文；遵守保留和汇总策略 |
| 敏感个人信息 | 邮箱、登录会话、审计主体 | 最小展示、按角色访问、记录生命周期 |
| 凭据与密钥 | 密码哈希、OAuth Token、代理凭据、API Key | 按既有哈希或 AES-256-GCM 模型保存，不写日志 |
| 支付业务 | 用户会员、房主名额覆盖、付款订单、商户快照、后台支付配置 | 金额用整数分；用户只读自己的订单，管理员可核实用户订单；商户密钥加密、不回显、不写日志；配置仅管理员可读写 |

## 生命周期与保留

- 登录会话和 OAuth flow 按到期时间清理。
- 已读通知、终态邀请、终态申请和无指标引用的已撤销 API Key 按配置保留期分批清理。
- 网关原始指标默认保留 90 天，并在删除前汇总为 UTC 日级数据。
- 审计事件默认保留 365 天。
- 清理任务使用有界批次和 `SKIP LOCKED`，避免长事务阻塞在线请求。
- 实际默认值和最小限制以 `backend/internal/config/config.go` 为准。
- 会员付款订单、用户权益和会员制启用时间不进入短期清理任务；会员订单关联用户，不关联 Plan，删除 Plan 不删除付款历史。管理员调整与付款发放留审计记录。支付规则及异常处理见 `docs/membership.md`。

## 指标口径

- 份额使用整数基点，`10000` 表示 100%。
- 上游额度百分比使用整数 micros，避免浮点累计误差。
- 费用使用整数 micros。
- “今日”按调用方提交的 IANA 时区计算；日级历史汇总使用 UTC 日期。
- 5 小时和 7 天窗口按固定时长识别，不依赖响应头顺序，也不使用其他字段猜测。
- 指标和额度的详细归属公式以 `docs/architecture.md` 为准。

## 变更检查清单

新增字段、表、指标或审计事件前必须回答：

- 数据解决哪个已确认业务问题？
- 数据所有者和可访问角色是谁？
- 是否包含个人信息、凭据或可关联行为？
- 精确单位、时区、窗口和空值语义是什么？
- 原始数据保存多久，何时汇总或删除？
- 删除用户、Plan、账号或成员关系时如何处理？
- 是否需要索引、唯一约束、外键或 `CHECK` 约束？
- API、Go 类型、前端类型、文档和测试是否同步？

没有明确答案时，不创建字段或 migration，先确认业务含义。

## 并发分钟记录

`account_concurrency_minutes` 用于 Plan 内查看账号总并发及各成员占用，属于行为指标。仅保存账号、Plan、绑定代次、采集器标识、UTC 分钟、已观测秒数、总峰值，以及用户 ID、用户名和请求占用秒数；不保存请求正文、完整响应、API Key 或 session 内容。当前有效 Plan 成员和平台管理员可读取当前绑定代次的记录，房主和管理员可修改分配配置，修改留审计。

分钟记录保留 48 小时，资源清理任务用有界批次和 `SKIP LOCKED` 删除；Plan 或账号删除通过外键级联删除其历史。成员退出清零分配，但已发生的短期并发记录仍保留至到期，确保总量可解释。用户 ID 和用户名可能在该短期窗口内留在聚合 JSON 中。内存观测只保留约 25 小时。历史是从采集启用后产生的数据，崩溃前未持久化片段与未观测时间段不能标记为准确历史或补零。

### Codex STATE 票据与作业

业务所有者为账号所有者；STATE 属敏感凭据，仅服务端访问，沿用 credential key 的 AES-GCM，AAD 绑定账号、模型、配置指纹和票据版本。`codex_state_jobs` 保存每账号最多 8 个模型的密文、租约、时间、尝试次数与最近一轮脱敏结果，不持久化请求/响应正文、原始错误、代理密码或活动历史。账号所有者与管理员只能读取脱敏状态。

票据 60 分钟过期后不再注入；任务/密文在 24 小时无业务使用后由 worker 删除。关闭、账号状态/套餐/代理/指纹/刷新凭据变化立即删除，账号删除级联删除。数据库备份沿用现有备份保留策略。探测会使用上游额度，但不归入成员业务请求计费，UI 明示。`attempts` 为当前模型任务累积采集轮数；删除并重建任务后重置。
